# PRoot v5.4.1

PRoot v5.4.1 is out. This release is about a moment nobody thinks of as a decision, which is the moment a program you're running calls a syscall proot has never seen before.

For anyone new here: PRoot is a free and open source user-space implementation of chroot, mount --bind, and binfmt_misc. Think chroot, but without needing root, and without a container runtime underneath it.

## clone3 syscall support

Every process and thread a traced program starts has to pass through proot first, and for years that meant recognizing one syscall: clone. Modern glibc increasingly reaches for clone3 instead. A program built against it would hit a syscall proot didn't know, with no guarantee of what happened next. proot now traces clone3 the same way it always traced clone.

## A readlinkat(2) bug that aborted the whole session

One bad syscall used to take down the whole session, not just the program running it. readlinkat(2) called with an empty pathname on a dirfd opened O_PATH|O_NOFOLLOW, a common pattern for resolving a symlink's target safely, aborted the tracer outright. Not the traced program. The tracer. Every process under supervision stopped at once. That's fixed now ([#182](https://github.com/proot-me/proot/issues/182)).

## Fixing the release we almost shipped broken

The static build of proot and care failed to link because of the Python extension and libarchive's static dependencies, and it failed on the actual v5.4.1 release run. This release fixes it, along with hardening most users will never notice: CodeQL scanning, Dependabot, GitHub Actions pinned to commit SHAs, and Docker test images moved off end-of-life bases to ghcr.io.
