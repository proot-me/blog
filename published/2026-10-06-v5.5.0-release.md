# PRoot v5.5.0

PRoot v5.5.0 shipped last week, with an overhaul of the test suite, [`fchmodat2()`](https://www.man7.org/linux/man-pages/man2/fchmodat2.2.html) syscall support, and fixes for three real compatibility bugs that show up on newer Linux distros.

Here's what you need to know:

* The test suite got a substantial overhaul. A [Bats](https://github.com/bats-core/bats-core)-based black-box suite now runs the same test files as a conformance check against both PRoot and [proot-rs](https://github.com/proot-me/proot-rs). A new [libcheck](https://libcheck.github.io/check)-based layer unit-tests PRoot's internal functions directly, instead of only being reachable through a full traced process. And the 122 test files that used to have opaque hash names, like `test-5bed7141.c`, were renamed to names that describe what they actually test.

* PRoot now recognizes the [`fchmodat2()`](https://www.man7.org/linux/man-pages/man2/fchmodat2.2.html) syscall. Linux 6.6 added it so `fchmodat()` callers could pass `AT_SYMLINK_NOFOLLOW`, something the older syscall can't do, and glibc 2.39 started using it.

* Fixed a bug where PRoot reported the loader's own name instead of the traced program's through `AT_EXECFN`. This broke [uutils](https://github.com/uutils/coreutils), the Rust rewrite of GNU coreutils that Ubuntu 25.10 and newer ship by default, since it uses `AT_EXECFN` to figure out which command it was invoked as.

* Fixed [`readlink(2)`](https://www.man7.org/linux/man-pages/man2/readlink.2.html) silently truncating its result and reporting the wrong guest path whenever the host-side target was longer than the caller's buffer.

* Fixed `PR_GET_NO_NEW_PRIVS` reporting PRoot's own `no_new_privs` flag instead of the traced program's. PRoot sets that flag on itself to install its seccomp filter, but the kernel can't tell the difference between PRoot asking and the traced program asking, so the program used to get PRoot's answer. This broke [`sudo-rs`](https://github.com/trifectatechfoundation/sudo-rs), Ubuntu 26.04's default `sudo`, which refuses to run once it sees the flag set.

You can find out more about the release here: [v5.5.0 release notes](https://github.com/proot-me/proot/releases/tag/v5.5.0).
