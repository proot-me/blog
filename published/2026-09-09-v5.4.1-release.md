# PRoot v5.4.1

PRoot v5.4.1 shipped earlier this week, with [CodeQL](https://codeql.github.com), [Dependabot](https://docs.github.com/en/code-security/tutorials/secure-your-dependencies/dependabot-quickstart), and [SonarCloud](https://www.sonarsource.com/products/sonarqube/cloud) configured to catch security issues earlier in the SDLC, [`clone3()`](https://lwn.net/Articles/792628) syscall support, and a fix for a bad [`readlinkat()`](https://www.man7.org/linux/man-pages/man2/readlink.2.html) call that could abort an entire session.

Here's what you need to know:

* CodeQL and Dependabot are now enabled on the repository, and SonarCloud was configured for automatic PR analysis, to catch security issues sooner.

* PRoot now recognizes the [`clone3()`](https://lwn.net/Articles/792628) syscall, which newer versions of glibc use instead of [`clone()`](https://www.man7.org/linux/man-pages/man2/clone.2.html) to create processes and threads.

* Fixed a bug where a bad [`readlinkat()`](https://www.man7.org/linux/man-pages/man2/readlink.2.html) call could abort the entire PRoot session, halting every process running under it instead of just the one that triggered the error.

You can find out more about the release here: [v5.4.1 release notes](https://github.com/proot-me/proot/releases/tag/v5.4.1).
